# Real cloud verification

All cloud successes below used the actual approved account and region. Unit tests use isolated fakes and are reported separately.

1. S3 Vectors canary Create/Put/Query/Get/List and DynamoDB conditional Put/Get passed. The original 60 embeddings and 11 metadata entries were migrated with read-back verification, without recomputing vectors. Five original queries ranked first (`AWS_GATE1_VERIFICATION.json`).
2. IAM API rejected unsigned requests with 403 and accepted server-side SigV4 with 200. Three Standard SSM values were retrieved (`AWS_API_VERIFICATION.json`).
3. A non-sensitive `cloud-stage-canary.txt` normal upload produced an actual S3 ObjectCreated event, EventBridge delivery, SQS consumption, deployed Lambda dispatch, successful Standard workflow, DynamoDB awaiting-local state, outbound local embedding/vector sync and searchable state. Derived content hash and original download bytes matched (`AWS_WORKFLOW_VERIFICATION.json`).
4. The user-requested water fixture was restored once through the **normal CloudVault multipart upload API** after automated Brave file selection was blocked. No direct S3 restoration or database insertion was used. Its new file ID is `b39aa36d-d2b7-475e-bca0-06739093298c`. An initial native-event watcher timed out before that upload; that failed attempt remains in `history/v3/water-event-window-timeout.json`.
5. The existing restored object was then reconciled through a real SQS message and the same Lambda/workflow. This was **manual reconciliation**, not a claimed native EventBridge delivery for water. It reached searchable, ranked first through actual QueryVectors, downloaded identical bytes and generated a cited Qwen answer (`AWS_WATER_RESTORATION_VERIFICATION.json`). The separate canary proves the native route.
6. A deployed partial-batch rejection, controlled real SQS redrive after receives 1/2/3, missing-managed-object workflow Catch/terminal failure and duplicate-event idempotency passed (`AWS_FAILURE_VERIFICATION.json`). The DLQ redrive driver was local bounded SQS receives; it is not represented as a full Lambda poison-message experiment.
7. Real structured logs and native invocation/error/duration metrics were read with a bounded snapshot (`AWS_MONITORING_VERIFICATION.json`). Intentional negative tests may contribute errors; absent datapoints mean unavailable, not zero.
8. After restoration, all 10 predefined semantic cases ranked their expected document first using S3 Vectors; the same stored vectors also ranked first locally. This small curated set is not a general accuracy percentage (`RETRIEVAL_EVALUATION_V3.json`).
9. Read-only preservation verified all 10 unaffected original documents/keys/hashes, 59 exact original vector blobs/text, and prior conversations/exchanges. S3 HEAD confirmed original existence and size. Exact restored download bytes were checked separately (`PRESERVATION_VERIFICATION_V3.json`).

Both event rule and queue mapping were confirmed disabled at handover. Storage, cloud dense queries, signed metadata and local generation stay usable. The synthetic DLQ/failure evidence is retained, not silently purged. No unrelated file was deleted by restoration or these verification scripts.
